# Fetchdeck v1.2 Browser Extension Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Chrome/Edge extension that hands browser downloads to Fetchdeck (auto-capture, right-click, logged-in downloads), with the local server, credential handling and UI it needs.

**Architecture:** The engine learns to send `Cookie`/`Referer`/`User-Agent` (cookie only to the original origin); the queue keeps them in an injected, encrypted `AuthStore`. The app runs a token-protected local server on 127.0.0.1:47600 that feeds a capture line shown one at a time in the Add dialog. A new `extension/` workspace package (Manifest V3, esbuild) pauses the browser download, posts it to the server, and cancels or resumes it by the answer.

**Tech Stack:** TypeScript strict, Node 22 `http`, Electron 45 `safeStorage`, React 19, Vitest, esbuild, `@types/chrome`, Playwright (extension e2e only).

**Spec:** `docs/superpowers/specs/2026-11-06-v1.1-browser-extension-design.md` (revised 2026-11-07). Read it first; section numbers below refer to it.

## Global Constraints

- Node `>=22.12`; ESM; TypeScript `strict`; no `any`; no `as` casts except where existing code already uses them (prefer type guards).
- Server: `http` bound to `127.0.0.1`, fixed port `47600`, off by default (`extensionEnabled: false`). API `/v1`: `GET /v1/ping`, `POST /v1/captures` (202 `{ captureId }`), `GET /v1/captures/:id?wait=20`.
- Checks on every request, in order: Host is `127.0.0.1:47600` or `localhost:47600`; `Authorization: Bearer <token>` via `timingSafeEqual` (token = 32 random bytes; 10 failures in a minute gives 429 for a minute); `Origin`, if present, starts with `chrome-extension://`; body at most 64 KB, JSON only, URL through `asUrl`, only allowed keys, length-limited values, control characters rejected.
- Capture line: at most 20 pending; one dialog at a time; a capture whose extension stops polling for 60 s is dropped; the long-poll waits at most 20 s.
- Allowed credential headers: only `Cookie`, `Referer`, `User-Agent`. The engine's own `Range`, `Accept-Encoding`, `If-Range` always win. `Cookie` goes only to the origin of the original URL (`record.url`). Credentials never enter `DownloadRecord`, `DownloadView`, logs or the renderer.
- Credentials: encrypted on disk with Electron `safeStorage` as `<id>.auth`; deleted when a download finishes, is cancelled or removed; kept on `error`; memory only (never plaintext on disk) when encryption is unavailable.
- Extension: Manifest V3; permissions `downloads`, `contextMenus`, `storage`, `cookies`, host permissions `http://127.0.0.1:47600/*` and `<all_urls>`; captures http(s) downloads with known size at or above 5 MB (adjustable); unknown sizes, `blob:`, `data:` and already-complete downloads stay in the browser.
- The extension never leaves a browser download paused: any failure (app unreachable, wrong token, 4xx/5xx, 3 failed polls) resumes it.
- Version 1.2.0 for app, engine, queue and extension. Branch `feat/v1.2-extension` from `fix/v1.1.1` (`main` does not have v1.1.x yet).
- Commit messages are `type(scope): subject` and end with these two lines:
  `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`
  `Claude-Session: https://claude.ai/code/session_015CenuBJPBktmwV5GEea11z`
- `npm run check` (lint, typecheck, test) must pass before every commit. Docs are updated in Task 12 only.
- `app/main/captureLine.ts` and `app/main/extensionServer.ts` must not import `electron` (the extension e2e test runs them in plain Node).
- Build in a Linux copy, because this folder's `node_modules` holds Windows-only binaries (see Task 1). Do not push to GitHub unless Tejas asks.

## Review Focus

1. A cookie value appearing anywhere except an outgoing engine request: `DownloadRecord` JSON, `DownloadView`, the `captures.onIncoming` payload, error messages, log lines (Tasks 2, 3, 7).
2. Hostile or malformed capture bodies: `file:`, `javascript:`, `blob:`, `data:` URLs, links over 2048 characters, CR/LF or other control characters in cookie/referer/user-agent, unknown keys, `null`/array bodies, wrong content type (Task 6).
3. Browser downloads that must not be captured: already complete when the handler runs, unknown size (`-1`), `blob:`/`data:`, the same download id reported twice. The browser download must continue untouched (Tasks 9, 10).
4. The app disappears while captures wait: the Settings switch turns the server off, the app quits, or the port is busy at start. Pending long-polls end as dismissed so the browser download resumes and nothing stays paused (Tasks 5, 6, 10).
5. The token is regenerated or wrong mid-wait, or the lockout trips: the extension gets 401/429 and resumes the browser download (Tasks 6, 10).
