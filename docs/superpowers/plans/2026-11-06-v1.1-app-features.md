# Fetchdeck v1.1 Spec A (settings, queue reordering, notifications) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Settings screen, queue reordering that survives restarts, and completion/error notifications to Fetchdeck.

**Architecture:** The queue persists its line order in `order.json` and gains `moveUp`, `moveDown`, `startNow`, `setMaxConcurrent` and `setMaxSegments`. The app main process gets a validated `settings.json` store, new IPC channels, and a notifier. The renderer sorts by a new `DownloadView.position` and gets a Settings dialog and new row-menu items. The engine's behavior does not change.

**Tech Stack:** TypeScript (strict), Node 22.12+, Electron 45, React, Vitest (jsdom for renderer tests), npm workspaces `engine`, `queue`, `app`.

**Spec:** `docs/superpowers/specs/2026-11-06-v1.1-app-features-design.md`

## Global Constraints

- Node `>=22.12`; ESM; TypeScript `strict`; no `any`; no `as` casts except where existing code already uses them (prefer type guards).
- Settings ranges and defaults: simultaneous downloads integer 1..6 (default 3); connections per download integer 1..8 (default 8); notifications boolean (default on); save folder default is `app.getPath('downloads')`.
- File names: `order.json` in the queue `stateDir`; `settings.json` in `app.getPath('userData')`. Both are written temp-file-then-rename (with `sync` before the rename), and a missing or corrupt file never blocks startup.
- Setting scope: save folder and connections apply to downloads added afterwards; the simultaneous limit applies live and never stops a running download.
- The page never sends a raw path: the save folder changes only through `chooseFolder`, validated in main. `settings:update` rejects unknown keys.
- Notifications: done and error only, only when the window is not focused (minimized and hidden count as not focused), click on done shows the file, click on error focuses the app. Restored records never notify.
- Windows notification app ID is `com.fetchdeck.app` (the `appId` in `app/electron-builder.yml`).
- Tests use the fake server in `engine/test/helpers/fakeServer.ts` and temp folders; `npm run check` (lint, typecheck, test) must pass before every commit.
- Work on branch `feat/v1.1`. Commit messages are `type(scope): subject`, ending with the same `Co-Authored-By` and `Claude-Session` trailer lines as the spec commits.
- Docs are updated in Task 10 only.

## Review Focus

1. `order.json` that lists ids with no record, repeats an id, or holds non-strings: unknown and repeated ids are ignored, records it omits go last by `createdAt` (Task 1).
2. `startNow` when the running download it pauses has already finished: a finished download is never put back in line (Task 2).
3. Settings patches that look valid but are not: `NaN`, `2.5`, `'3'`, `0`, `7`, `null`, arrays, extra keys, and `saveDir` smuggled into `settings:update` (Tasks 4, 5).
4. The saved folder was deleted or sits on an unplugged drive at startup: fall back to the default folder instead of failing every new download (Task 4).
5. A download restored as `done` or `error` from disk, or a repeated `changed` event with an unchanged status, must not fire a notification (Task 6).

2. Set simultaneous downloads to 1, add 3 downloads: one runs, two wait; set it to 3: the waiting ones start.
3. With 3 queued: Move up/Move down change "#n in line"; Alt+Up/Down do the same; restart the app: order is kept.
4. Start now on a queued item while another runs at limit 1: the other goes back in line and finishes later with a correct file.
