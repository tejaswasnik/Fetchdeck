# Fetchdeck v1.1, Spec A: settings, queue reordering, notifications

Date: 2026-11-06
Status: draft for review
Part of v1.1. Spec B (browser extension) is written separately; both ship in one release, A first.

## Goal

Remove the main v1 limits for daily use: the save folder is fixed to Downloads, the queue cannot be reordered, and nothing tells you when a download finishes or fails.

## Scope

In:
- A Settings screen: save folder, simultaneous downloads, connections per download, notifications on/off.
- Queue reordering: Move up, Move down, Start now. Order survives restarts.
- System notification when a download finishes or fails.

Out (not in this spec):
- Browser extension (Spec B).
- Speed limit, scheduling, checksums, drag-and-drop reordering, per-connection speeds, a first-run screen.
- Any change to the `engine` package or the `DownloadRecord` type.

## Decisions

| Question | Decision |
|---|---|
| Split of v1.1 | Two specs, one release. A first, then the extension. |
| Where order lives | `order.json` in the queue's state folder, not a field on the record. |
| When settings apply | Save folder and connections: new downloads only. Simultaneous limit: live. |
| Start now at the limit | Pause the most recently started running download, start the chosen one, put the paused one right behind it in line. |
| Notifications | Done and error, only when the window is not focused. Click on done shows the file; click on error focuses the app. |
| Settings library | None. A small validated JSON store, same style as existing IPC validation. |

## 1. Queue changes (`queue/`)

Today line order is the insertion order of the `entries` map, and `load()` re-sorts by `createdAt`, so "back of the line" is lost on restart. `maxConcurrent` and `maxSegments` are fixed at construction.

- **Persisted order.** `order.json` (a list of ids) in `stateDir`, written with the same temp-file-then-rename as records. Saved on add, resume, move, start now, cancel and remove. `load()` sorts by it first; records not listed fall back to `createdAt`. A missing or corrupt file emits `'warning'` and falls back to `createdAt`; it never blocks startup.
- **`moveUp(id)`, `moveDown(id)`.** Swap a `queued` download with its nearest `queued` neighbour. No-op at the ends and for items that are not queued. Emit `'reordered'` with the new id list.
- **`startNow(id)`.** Works on a queued, paused or errored item. Moves it to the front. If a slot is free it starts at once. If the limit is reached, it pauses the most recently started running download, sets that one back to `queued` directly behind the chosen item, then schedules. The paused download resumes from its saved offsets. Each entry gets a start counter to find the newest.
- **`setMaxConcurrent(n)`.** Clamp to 1..6, applies live. Raising calls `schedule()`. Lowering never stops running downloads; nothing new starts until the running count is below the limit.
- **`setMaxSegments(n)`.** Clamp to 1..8. Affects downloads registered afterwards only.
- **Save folder.** Stays a per-download field on the record. The app passes the current folder into `add`.

## 2. Settings store, IPC and notifications (`app/main/`)

**Settings store (`settings.ts`).** Shape `{ saveDir, maxConcurrent, maxSegments, notifications }`. Stored in `settings.json` in the user-data folder (temp-file-then-rename). Defaults on a missing or corrupt file: system Downloads folder, 3, 8, notifications on. Replaces the module-level `setDefaultSaveDir` in `ipc.ts`; `add`, `preview` and `info` read the store. An update applies to the queue immediately (`setMaxConcurrent`, `setMaxSegments`); later `add` calls use the new folder.

**Security.** The page never sends a raw path.
- `settings:chooseFolder`: main opens `dialog.showOpenDialog` itself and checks the folder exists and is writable.
- `settings:update`: a patch validated in main. Integers in range, a boolean for notifications, unknown keys rejected, in the style of `validate.ts`.
- `SystemLike` gains `chooseFolder()` so IPC stays testable without Electron.

**New IPC** (`app/shared/api.ts`, `CHANNELS`, preload, validation): `settings.get`, `settings.update`, `settings.chooseFolder`, `moveUp(id)`, `moveDown(id)`, `startNow(id)`. `DownloadView` gains `position` (index in `queue.list()`). On `'reordered'`, main resends the affected views.

**Notifier (`notifier.ts`).** Watches queue `'changed'` events and fires once on a transition into `done` or `error`. The first status seen for an id is recorded without notifying, so records restored by `load()` stay quiet. Fires only when `notifications` is on, the window is not focused (minimized and hidden count as not focused), and `Notification.isSupported()` is true. Click on done: `showItemInFolder` for the file. Click on error: `revealWindow`. Electron and clock are injected, like `quitGuard`. On Windows, `app.setAppUserModelId` is set to the `appId` in `electron-builder.yml`; the plan must confirm they match.

## 3. UI (`app/renderer/`)

- **List order.** `useDownloads` and `queuePosition` sort by `position` instead of `createdAt`, so "#n in line" follows reordering and restarts.
- **Settings entry.** A Settings button at the bottom of the sidebar opens `SettingsDialog` (same modal pattern as `AddDownloadDialog`).
- **Settings dialog.** Save folder (read-only path plus Change... button); simultaneous downloads stepper 1..6; connections per download stepper 1..8; notifications switch. No Save button: each change calls `settings.update`, errors show inline and the control snaps back to the saved value. Helper text: "Applies to new downloads" (folder, connections), "Applies right away" (simultaneous). After a folder change, re-fetch `info()` so the top bar and free space update. Esc closes, focus is trapped, controls have labels and roles.
- **Reordering.** `RowMenu` gets Move up and Move down (shown for items in line, disabled at the top and bottom) and Start now (shown for in line, paused or errored). Keyboard: Alt+Up and Alt+Down move the selected item; ignored while typing. No drag-and-drop.
- **Docs.** Remove the delivered items from "Not in v1" in the README; add a CHANGELOG entry.

## Error handling

- Corrupt `order.json` or `settings.json`: warn, fall back to defaults, keep running.
- Invalid settings patch: rejected in main with a plain message, shown inline.
- Folder not writable or missing: rejected with a plain message; the previous folder stays.
- Reorder or Start now for an id that no longer exists: plain "no longer in the list" error, like the existing handlers.

## Testing

Queue: persisted order survives `load()`; corrupt `order.json` is skipped with a warning; moves are no-ops at the ends and on non-queued items; `startNow` with the limit full pauses the newest running one and the resumed file is byte-identical; raising and lowering the limit; `shutdown` still works; existing crash test stays green.

App main: settings defaults on missing/corrupt file, patch validation, round-trip save, live application to the queue; each new IPC channel routes correctly and rejects bad arguments; notifier fires once per transition, not while focused, not when disabled, not for restored records, and the click actions.

Renderer (jsdom): list sorts by `position` and "#n in line" updates after a reorder push; row menu shows and disables the right items per status; settings dialog renders values, sends the right patch per control, shows an inline error and snaps back, refreshes `info` after a folder change; Alt+Up/Down work and are ignored while typing.

`npm run check` stays green on Windows and Linux CI.
